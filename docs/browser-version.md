# ブラウザ版 Eduba

デスクトップ版と React UI、PDF.js、画像前処理、校正データ、出力生成を共有する。
ブラウザ版は静的ファイルだけで配信でき、PDF・校正内容・推論画像をサーバーへ送信しない。
Tesseract.js、ONNX Runtime Web、SQLite WASM は端末内で動く。

## 開発と配信

初回は `npm install` を実行し、OCR モデルを配置する。
モデルは Git 管理対象外なので、新しい worktree では既存のモデルを明示的に指定できる。

```powershell
npm run prepare:web -- --model 'src-tauri/resources/models/eng_assyriology_charset_expanded_250x_20261023.traineddata'
npm run dev:web
```

開発用 URL は `http://127.0.0.1:1421`。
`EDUBA_WEB_MODEL` にモデルパスを設定することもできる。
モデルを配置した後は `npm run build:web` で配信用の `dist/` を生成する。
`npm run preview:web` で配信用ビルドを確認できる。
HTML、JS、Worker、WASM、traineddata、ONNX、フォント、ライセンスを含む `dist/` 全体を配信する。
ビルド・開発に Node.js が必要だが、配信サーバーに Node.js や Rust は不要。

HTTPS（ローカル確認は localhost/127.0.0.1）を使用する。
WASM の Content-Type は `application/wasm`、JS/MJS は JavaScript の MIME type にする。
相対パスでビルドするためサブディレクトリにも配置できる。
SQLite は OPFS SAH pool、ONNX は WASM 1スレッドを使用し、COOP/COEP ヘッダーを必須にしない。
依存コード、学習モデル、推論モデルの取得先は同一サイト内の静的資産のみ。
この段階では Service Worker によるオフライン起動は実装していない。

配信用ブラウザビルドは Cloudflare Web Analytics のビーコンを読み込み、ページビューと表示速度を Cloudflare に送信する。SPA の画面遷移も Cloudflare の標準機能で計測し、独自の操作イベントは送らない。Cloudflare は個人をサイト間で追跡しない。PDF、画像、OCR・校正内容は送信しない。計測スクリプトを読み込めなくてもアプリの処理は継続する。デスクトップビルドと開発サーバーにはビーコンを含めない。Web Analytics の自動挿入を Cloudflare 側で有効にすると重複するため、手動スニペット方式を使用する。

Starlight のドキュメントとまとめて配信する場合は `npm run build:website` を使用する。
固定した Release の OCR モデルを取得・SHA-256 検証してからアプリをビルドし、
`website/public/app/` を経由して `website/dist/app/` に配置する。
初回のモデル公開、ローカルでのビルド、CI の構成は [サイト公開手順](website-deployment.md) を参照する。

## ローカルファイルと自動保存

- 開始画面には PDF からの新規作成、`.eduba` を開く、ブラウザ内の作業コピーを開く操作を表示する。作業コピーを開くボタンは、保存済みのプロジェクトがあるときだけ有効にする。
- PDF、`.eduba`、独自の `.traineddata` をユーザーが選択して読み込む。
- 作業内容は OPFS 上の SQLite に自動保存する。原稿 PDF は1 MiB単位で格納し、必要な範囲だけ読み出す。
- PDF の取り込みでは保存先を選ばず、ブラウザ内に作業コピーだけを作成する。プロジェクト名は元の PDF のファイル名から付ける。
- 「プロジェクトを保存」「名前を付けて保存」で `.eduba` ファイルを書き出す。最初の明示的な保存時に、保存先を選択するかファイルをダウンロードする。
- File System Access API 対応ブラウザでは選択したファイルへ上書きする。非対応ブラウザではファイルをダウンロードする。
- Ctrl+S はファイル保存、Ctrl+Shift+S は名前を付けて保存。自動保存の通知はファイル保存の通知と区別する。
- 再読み込み時は直前の作業コピーを復元する。「作業中のプロジェクト」から以前の作業コピーを開ける。
- 一覧では現在開いている作業コピーを先頭に固定し、「現在のプロジェクト」と表示する。残りは最終編集日時の新しい順とし、日時が不明なものは末尾に置く。同じ日時の場合や不明なもの同士は名前順とし、同名の場合は内部 ID で順序を固定する。
- 一覧には端末へのファイル保存を促す説明と「保存データの保護」の状態を表示する。ダイアログを開いたときに `navigator.storage.persisted()` で確認し、許可済みなら「有効」、未許可なら「無効」、API 非対応や確認失敗時は「確認できません」とする。フォーカス復帰時と永続保存の要求完了時にも再確認する。一覧を開くだけでは永続保存の許可を要求しない。プライベートブラウズを推測・判別せず、終了時にデータが削除される可能性を共通の注意書きとして表示する。
- 作業コピーの一覧に論理ページ数、データ容量、ブラウザでの最終編集日時を表示する。容量は PDF・OCR 結果・校正履歴と SQLite の管理領域・再利用待ち領域を含む DB 本体のサイズ（MiB 等）で、ブラウザの保存領域全体の使用量ではない。日時は内容の変更を保存したときに記録し、一覧の表示・再オープン・ファイルの書き出しだけでは更新しない。記録開始前のプロジェクトなど、日時の記録がない場合は「不明」と表示する。
- 「作業中のプロジェクト」の各行にある「削除」で、確認後にその作業コピーだけをブラウザから削除できる。PDF・ページデータ・校正履歴を含むDBを閉じて削除し、保存先ハンドルや復元設定も解除する。開いている場合はプロジェクトを閉じる。端末に保存済みの `.eduba`、他の作業コピー、設定、独自モデルは保持する。
- 再起動後はファイル保存先を再選択する。ブラウザ内の復元とOS上のファイルへの書き込み権限は別に扱う。
- 独自 traineddata は IndexedDB に保存する。モデル自体は `.eduba` に埋め込まず、別端末では選択し直す。
- ブラウザ版の設定画面の「基準モデルに戻す」で、独自モデルの指定をサイトの基準モデルへ変更できる。変更は作業コピーへ自動保存し、次回の OCR から適用する。既存の OCR 結果・校正内容と、ブラウザに保存した独自モデル本体は保持する。基準モデル使用中はこのボタンを無効にする。

OPFS/IndexedDB はサイトごとに保存される。サイトのURLを変えたりサイトデータを削除したりすると、以前の作業コピーや独自モデルは使えなくなる。
保存容量はブラウザの制限を受け、永続保存の要求が許可される保証はない。持ち運び・バックアップには `.eduba` を保存する。
作業コピーは自動削除しない。容量を整理するときは必要な `.eduba` を保存し、「作業中のプロジェクト」から不要なコピーを削除する。
OPFS の競合を避けるため、同じサイトで同時にプロジェクトを扱うタブは1つに限る。

## プロジェクト互換性

`.eduba` はデスクトップ版と同じ SQLite schema version 1。
`meta`、`pdf_chunks`、`pages`、`edit_history_records` と gzip 圧縮の履歴を保持する。
ブラウザ用の表示名は任意の `meta.browser_name` に記録する。
ブラウザでの最終編集日時は任意の `meta.browser_modified_at` に UTC の ISO 8601 形式で記録し、UI では利用者のタイムゾーンと表示言語に合わせて表示する。
OPFS では DELETE journal を使用し、外部ファイルへはSQLite本体を出力する。
ページ更新、manifest、Undo/Redo の保存は1つのトランザクションにまとめ、古い編集内容を前提にした更新は拒否する。
デスクトップ上の絶対モデルパスはブラウザで利用できないため、ブラウザで開くと既定モデルを使用する。必要なら設定画面で独自モデルを選択する。
ブラウザ側のモデル識別子を含むプロジェクトをデスクトップで開いた場合も、デスクトップ側の既定モデルを使用する。

## OCR と自動判定

既定モデルは Assyrian-OCR の `eng_assyriology_charset_expanded_250x_20261023`。
2026年10月24日に学習・評価の基準として採用された、文字集合拡張実験の250回/行モデルを取り込む（学習4,267行、dev評価1,082行）。
モデル名の日付は実験開始日で、採用日はその翌日。最終300回/行チェックポイントではなく、登録された250回/行の成果物を使用する。
モデルの識別子、SHA-256、取得先は `config/web-model.json`、学習側の記録は `docs/ocr-model-provenance.json` に保存する。
Web 版の既定ファイル名とビルド時の配置先は manifest を共有する。
デスクトップ版の既定モデルとセットアップ用のパスも同じモデルに更新している。
デスクトップ版の既存プロジェクトで明示されたローカルモデルのパスは、そのまま使用する。
旧ブラウザ版の2026年10月15日モデルのファイル名も、ブラウザ既定モデルの識別子として読み込める。
校正候補は、使用中の OCR モデルが `lstm_choice_mode=2` で返す文字別候補と、同梱基準モデル専用の文字混同表を併用する。表示順は LSTM 候補（`x_confs` スコア順）、表にだけある候補（出現件数順）、残りの転写・添字の変換候補とする。同点では各ソースの元の順を保つ。元の選択文字と同じ候補は除外し、NFC で等価な候補は先に出た表記を一度だけ表示する。表示する文字列自体は正規化しない。LSTM スコアと表の件数を混ぜて順位付けせず、どちらも校正の正解確率とは扱わない。独自モデルを使用する場合も、表は同梱基準モデルに由来する参考候補である。
LSTM 候補とスコアは任意の文字データとして `.eduba` に保持する。旧 OCR 結果に LSTM 候補がない場合も候補表を使用できるが、その箇所の LSTM 候補を得るには OCR の再実行が必要。編集後は最小編集距離の全対応で同じ元文字に一致する場合だけ LSTM 候補を使い、曖昧な文字や隣の文字からは借用しない。長大な行では処理量を制限する。結合文字を含む選択は元の Unicode 表現を保つ。一括置換の LSTM 候補はダイアログを開いた元の選択箇所に限り、他の一致箇所の候補とは扱わない。
候補表は Assyrian-OCR の `data/<model-key>/scan-candidate-character-confusions.json` をモデルとセットで取り込む。モデル key・SHA-256・候補表のバイト数と SHA-256 を `config/web-model.json` と照合し、対応しない場合はビルドを停止する。共通の `artifacts/` にある別モデル用の表は取り込まない。

Tesseract.js 7.0.0 の Worker を再利用し、OEM 1、PSM、DPI、`hocr_char_boxes=1`、`lstm_choice_mode=2` を設定して hOCR を取得する。
既存の浮動小数点モデルは自動選択されるSIMDコアで未実装のSSE関数を呼ぶ場合があるため、初期実装では非SIMDのLSTMコアと `dotproduct=generic` を指定する。速度の最適化は今後の課題。
Eduba側で実行済みの画像前処理を再適用しないよう、OCRエンジンの自動回転は無効。
Worker の所有とメッセージ送受信を Eduba が管理し、traineddata の初期化中もキャンセルとエラーを処理する。
Worker プロトコルに依存するため Tesseract.js を固定し、更新時はブラウザの実OCRテストも実行する。

図表検出と単語書式推論は既存の ONNX モデルを Worker で実行する。
図表のフィルター、重複除去、入力のRGB正規化、単語のpadding・白背景・Lanczos3縮小、判定しきい値をデスクトップ実装に合わせる。
浮動小数点演算と画像リサイズの差があるため、全入力で同じ認識・判定結果になるとは保証しない。
推論処理の中断は現在ページの処理の区切りで反映され、Tesseract OCR 実行中は Worker を終了する。

## 検証

```powershell
npm test
npm run build:web
npm run test:browser
```

ブラウザテストは既定でインストール済みの Microsoft Edge を使用する。
別のブラウザを使う場合は `EDUBA_TEST_BROWSER` に Playwright の channel（例: `chrome`）を設定する。
テストは配信用ビルドを使い、PDF読み込み、実OCR・ONNX推論、校正、SQLiteファイル保存、再オープン、Undo/Redo、リロード復元、hOCR座標メタデータを確認する。
ファイル選択・ダウンロードの互換方式と、Cloudflare ビーコン以外への外部リクエストがないことを確認する。テストではビーコンをスタブし、計測データを送らない。
ファイルハンドルでの直接保存、権限拒否、書き込み失敗からの再試行、名前を付けて保存、別タブとの競合防止、独自traineddataの読み込みも対象にする。
直接保存APIの権限拒否・書き込み失敗はテスト用ファイルハンドルで再現する。PDF.js、Tesseract.js、ONNX、OPFS、ファイル入力とダウンロードは実ブラウザで実行する。

2026-10-14 の実行結果: `npm run build:web` 成功、`npm test` 293件成功、`npm run test:browser` 2件成功（インストール済み Microsoft Edge）。外部サイトへの通信はテスト中に発生しなかった。

1,000ページ規模、モバイル、全ブラウザの性能・互換性は未確認。
外部ファイルへの保存時はSQLite全体のバイト列を一時的にメモリへ取り出すため、大きなプロジェクトでは保存時メモリが課題になる。
